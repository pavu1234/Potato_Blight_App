# Leaf Flight: severity, water status and 3D frontend

This package is a complete static website for the existing GitHub Pages repository. It includes the previously tested, field-fine-tuned disease model without changing its weights.

## Install
1. Extract `leaf_flight_severity_website.zip`.
2. Open https://github.com/pavu1234/tomato_prediction_website .
3. Upload the extracted files and folders to the repository root, replacing matching files. Preserve `vendor/three/` and all other folders. Do not upload the ZIP itself or put the contents inside an extra top-level folder.
4. Commit the changes and wait for the Pages deployment. Reload https://pavu1234.github.io/tomato_prediction_website/ .
5. The opening area should show a flying 3D drone and “See the leaf. Understand the next step.” Scroll to “Review & simulation.”

The package has not been automatically committed or deployed. The connected GitHub integration previously returned HTTP 403 for writes.

## Phase 1: default
Upload or capture a tomato leaf, then analyze it. The new assessment panel receives the actual classifier result. It shows disease confidence and manual-review status. Severity is “Not measured”; no infected-area percentage is shown and simulated duration is zero. Confidence is never used as severity.

## Phase 2: segmentation import
This release does NOT train or run a lesion-segmentation model. It implements the measurement and simulation module for externally produced segmentation masks.

1. Analyze the same photo first.
2. Select Phase 2 and upload a visible-leaf mask and a diseased-area mask as PNGs. Each must exactly match the original photo dimensions. White pixels (>127 average RGB, alpha >127) are included; black/transparent pixels are excluded. Disease pixels outside the visible-leaf mask are rejected. Maximum: 12 megapixels, 20 MB per mask.
3. Enter the segmentation model’s confidence. This is operator-entered source metadata, not a score generated by this website. The minimum is 80%.
4. Confirm you reviewed the masks’ alignment and select Validate masks. Matching dimensions alone cannot establish correct segmentation; operator review is necessary.
5. The module calculates diseased pixels / visible-leaf pixels × 100 and applies the specified severity bands. It shows the counts for review.
6. Enter a manual water level and confirm the screen-only simulation. High severity additionally requires recorded agronomist review. The button remains disabled if any gate fails. Critical severity always has zero duration and requires review.

Water level is a manually entered percentage. No sensor is connected. The timer does not deduct or estimate real water. No pesticide quantities, concentrations, mixing ratios or litres-per-hectare rates are calculated.

## Animation and hardware
The procedural WebGL drone is a generic 3D design, not a named real aircraft or live flight telemetry. It flies into the opening scene, then hovers. Pause/play, reduced-motion preference, offscreen/tab pausing and a static fallback are supported. Existing camera connections remain available. No flight, motor, valve or pump commands are implemented.

## Export
Download assessment JSON includes disease, confidence, severity mode, percentage only when valid segmentation is available, band, simulated duration, manual and agronomist review flags, operator confirmation, manual water status, reasons and the safety disclaimer. All state stays in this tab.

Simulation only. This duration is not a pesticide dose or real hardware command.
